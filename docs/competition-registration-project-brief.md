## 二、项目概述（300 字以内，适合系统填报）

CareMind 是一个面向**失能老人照护**垂直领域的多智能体协同个性化知识生成与决策系统。系统针对养老场景中护工医学知识不足、多药并用风险高、家属信息不对称三大痛点，构建了覆盖**医疗评估、护理评估、社工评估、膳食评估、跨域编排与决策审核**的 6 角色多 Agent 协同架构，形成"**多维度评估 → 冲突消解 → 安全审核 → 个性化输出**"的完整闭环。

不同于"千人一面"的静态照护指南，CareMind 的个性化生成引擎可根据接收方的**认知水平、方言背景和身份角色**（护工 / 家属 / 机构管理者），将同一照护事实转化为差异化的表达——为护工提供可操作的行动建议，为家属生成有温度的人性化叙事，为机构输出可留痕的结构化记录。

系统以**可追溯的老年医学知识底座**和**多层审核机制**作为安全兜底，在原型中已实现模拟案例驱动的全流程展示链路，并保留了接入真实大模型调用的工程扩展能力。CareMind 以 AI 赋能一线照护者，降低安全风险，弥合信息鸿沟，是"新质生产力"在养老服务领域的典型实践。

## 三、选题背景与问题陈述

### 3.1 宏观背景：老龄化已进入深水区

截至 2025 年末，中国 60 岁及以上人口已达 **3.23 亿**（占总人口 23.0%），65 岁及以上人口达 **2.24 亿**（占总人口 15.9%），中国正从中度老龄化向重度老龄化加速过渡。其中，**失能、半失能老人超过 4500 万**——这正是 CareMind 的核心目标用户群体。

与此同时，养老行业面临**结构性人力断层**：全国持证养老护理员仅约 50 万人，而保守估算缺口达 550 万人以上。一线从业者以 50-60 岁、高中及以下学历为主，月薪 3500-4000 元，行业流失率高达 30%-50%。**让这些受教育程度有限的一线护工获得医学级的风险识别能力，是养老行业最紧迫也最现实的智能化诉求。**

### 3.2 核心痛点：垂直领域知识传递的三重鸿沟

| 痛点 | 表现 | 本质问题 |
|------|------|----------|
| **护工能力鸿沟** | 看不懂血压/血糖异常含义，无法识别用药风险信号 | 领域知识无法以低门槛形式触达一线 |
| **多药并用风险** | 老年人平均服用 5-8 种药物，护工不知相互作用风险 | 高风险知识没有结构化、可检索、可提醒的载体 |
| **家属信息黑箱** | 家属只收到"体温 36.8℃，排便 1 次"的冰冷记录 | 专业知识未做个性化翻译，家属无法理解真实照护状态 |

这恰好回应了本次赛题的核心追问：**如何将大模型从"通用聊天工具"转化为"懂专业、精技能、能落地"的垂直领域基础设施？**

### 3.3 赛道契合度说明

| 赛题要求 | CareMind 对应 |
|----------|--------------|
| 面向垂直领域的技能培训场景 | 面向失能老人照护的垂直领域，适配护工、家属、管理者等不同背景用户 |
| 构建 ≥3 个职责明确的智能体 | 构建 6 角色多 Agent 协同架构（医疗/护理/社工/膳食/编排/决策） |
| 实现"分析-生成-校验-决策"协同闭环 | 实现"多维度评估 → 冲突消解 → 安全审核 → 个性化输出"完整链路 |
| 生成 ≥3 种形态的个性化学习资源 | 生成照护计划、风险预警、家属沟通报告、分阶指导等 |
| 知识高保真与零幻觉控制 | 建立分级知识来源体系 + 结构化输出约束 + 多层交叉验证 |

### 4.2 多智能体角色定义（对应赛题要求）

| CareMind Agent | 对应赛题角色 | 职责 | 输入 | 输出 |
|---------------|-------------|------|------|------|
| **医疗 Agent** | 学情诊断（生理维度） | 慢性病评估、用药审查、生理风险识别 | 病史、用药清单、生命体征 | 医疗风险等级、用药注意事项、需复核信号 |
| **护理 Agent** | 学情诊断（功能维度） | ADL/IADL 评估、跌倒风险评估、压疮风险评估 | 日常活动能力、行动记录、照护环境 | 护理风险等级、照护动作建议 |
| **社工 Agent** | 领域知识生成（心理社会维度） | 认知状态评估、心理情绪评估、家庭支持分析 | 心理评估、家庭结构、社交情况 | 心理照护建议、家属沟通叙事 |
| **膳食 Agent** | 领域知识生成（营养维度） | 营养风险评估、吞咽功能评估、饮食方案生成 | 体重、进食能力、慢病饮食约束 | 个性化膳食方案、禁忌提醒 |
| **Orchestrator Agent** | 协调调度中枢 | 接收 4 个评估 Agent 输出，进行跨域冲突消解与统一照护计划整合 | 4 份评估报告 | 统一照护计划草案、冲突标注 |
| **Decision Agent** | 内容审核与纠偏 Agent | 对统一计划进行三审（合理性/安全性/可行性），输出终审意见 | 统一计划 + 原始评估 | 终审照护计划、风险预警、修订建议 |

### 4.3 个性化生成机制（对应赛题"领域知识个性化生成"）

CareMind 的个性化生成体现在三个维度：

**维度一：接收方角色差异化**

同一份照护评估事实，系统根据接收方身份，生成不同风格和颗粒度的输出：

| 接收方 | 输出风格 | 知识颗粒度 | 语言特征 |
|--------|----------|-----------|----------|
| **护工** | 行动导向 | 操作级（做什么、观察什么、何时上报） | 简单直白，减少术语，强调动作指令 |
| **家属** | 叙事导向 | 状态级（老人整体怎么样、为什么、怎么办） | 温暖人性化，保留关键事实，避免冰冷数据 |
| **机构管理者** | 合规导向 | 流程级（记录、审核、政策对接） | 结构化、可追溯、满足长护险留痕要求 |

**维度二：知识难度自适应**

针对不同专业背景的护工，系统动态调整输出内容的医学深度：
- 对新手护工：强调"识别危险信号 → 立即上报"，规避复杂推理
- 对有经验护工：提供"可能原因分析 + 分级处理建议"

**维度三：至少 3 种资源形态**

| 资源形态 | 内容 | 示例 |
|----------|------|------|
| **定制化照护计划** | 针对性照护动作、频率、注意事项 | "每 2 小时协助翻身一次，观察骶尾部皮肤" |
| **风险预警报告** | 按风险等级分类的提示、建议复核项 | "检测到阿司匹林 + 布洛芬组合，建议联系药师复核" |
| **家属沟通报告** | 通俗化状态总结 + 照护叙事 | "奶奶今天精神不错，主动聊起年轻时的故事" |

### 4.4 反幻觉与知识保真机制（对应赛题"交叉验证与辩论"）

CareMind 采用**多层防御**策略确保知识高保真：

**第一层：知识底座分级约束**
- 建立 A/B/C 三级知识来源体系（A 级：国家指南、药品说明书；B 级：结构化 DDI 数据库；C 级：综述文献）
- 每条高风险规则必须满足"来源可追溯、风险可解释、人工已复核"三条底线
- 用药安全知识库采用结构化字段模板（药物组合、风险等级、机制、适用人群、来源引用）

**第二层：结构化输出契约**
- 每个 Agent 的输出由 JSON Schema 约束，防止自由发挥产生幻觉
- 高风险输出字段（如用药风险提示）强制携带 `source` 和 `evidence_level` 字段

**第三层：跨 Agent 交叉验证（对应赛题"辩论与交叉验证"）**
- Orchestrator Agent 比对 4 个评估 Agent 的输出，检测矛盾信号
- 当医疗 Agent 和护理 Agent 对同一风险的判断不一致时，标记为"需决策层复核"并上浮至 Decision Agent
- 这种"多视角交叉验证"机制本质上是对单一模型幻觉的系统性纠偏

**第四层：Decision Agent 终审**
- 对统一计划执行三审：**合理性**（是否符合医学逻辑）、**安全性**（是否存在遗漏风险）、**可行性**（是否符合机构实际照护能力）
- 所有涉及用药安全、重大风险判定的输出，系统显式标注"建议联系医生/药师复核"

## 五、创新点总结

### 创新一：将多智能体协同引入失能老人照护垂直领域（场景创新）

不同于常见的教育/培训/代码生成等 AI 应用场景，CareMind 将多 Agent 协同架构应用于**养老服务**这一社会刚需领域。系统不是简单地用大模型生成照护文本，而是构建了还原真实多学科会诊流程的 6 角色协同架构，在数字层面打通"医（医疗/用药）"与"养（护理/照护）"的信息壁垒——这正是国家"医养结合"战略的技术落地路径。

### 创新二："分析-生成-校验-决策"的完整闭环与跨域冲突消解（架构创新）

系统实现了赛题要求的完整闭环，其中 **Orchestrator Agent 的跨域冲突消解**和 **Decision Agent 的三审机制**是核心亮点：

- 当不同专业 Agent 对同一老人给出冲突建议时（如医疗 Agent 建议增加活动量、护理 Agent 因跌倒风险建议减少活动），Orchestrator 执行优先级消解并生成折中方案（如"在辅助下进行坐位活动，避免独立行走"）
- Decision Agent 作为独立审核角色，对整合后的方案进行终审，形成"评估-整合-审核"的多层质量防线

### 创新三：可追溯的知识底座与多层反幻觉机制（可信度创新）

在"大模型幻觉"这一赛题核心关切的应对上，CareMind 不走"事后检测"的单一路径，而是建立**事前约束（结构化 Schema）→ 事中交叉验证（多 Agent 比对）→ 事后审核（Decision Agent 终审）→ 输出标注（来源引用与风险边界）**的全链条防御。尤其是用药安全模块，已建立了 A/B/C 三级来源分级、字段模板和人工复核流程的制度化底座。

### 创新四：面向低门槛用户的差异化个性化生成（交互创新）

赛题强调"个性化适配"与"专业质量把控"的平衡。CareMind 的独特之处在于：它面对的用户不是同质化的"学习者"，而是**认知水平、方言背景、情感需求差异极大的三类人群**（低学历护工、焦虑家属、合规管理者）。系统的个性化不是简单的"推荐不同内容"，而是**同一照护事实在表达风格、语言难度、信息密度和安全边界上的差异化重构**——这比面向同质化学习者的个性化更具挑战，也更具社会价值。

## 七、预期成果与实用价值

### 7.1 技术成果

- 一套**可运行、可展示、可复现**的多智能体协同个性化知识生成原型系统
- 一个**可追溯、分级管理**的老年照护领域专业知识底座（聚焦用药安全）
- 一套**可评估**的幻觉防控与知识保真机制（Schema 约束 + 多 Agent 交叉验证 + Decision 终审）
- 一组**差异化学习者画像**测试用例与输入输出示例

### 7.2 社会经济效益

| 价值维度 | 具体表现 |
|----------|----------|
| **为护工赋能** | 让受教育程度不高的一线护工获得 AI 辅助的风险识别与照护支持能力，降低因知识不足导致的安全事件 |
| **为家属答疑** | 将冰冷的"血压/排便"数据转化为可理解、有温度的照护叙事，减轻"黑箱焦虑" |
| **为机构降本** | 通过知识数字化、风险前置和留痕改进，降低运营与沟通成本，提升照护质量可监督性 |
| **为政策衔接** | 系统输出的结构化照护记录可直接对接长护险（第六险）的评估与监管需求 |

### 7.3 可迁移性

CareMind 的多 Agent 协同架构与知识保真机制具备良好的领域泛化能力。同一套"学情诊断 → 多 Agent 协同生成 → 交叉验证 → 终审输出"的技术框架，可迁移至：

- **其他医疗健康垂直领域**：慢病管理、康复指导、妇幼保健
- **企业高标准化内训**：安全生产培训、合规操作指导
- **更广泛的终身教育场景**：职业技能培训、社区健康教育
