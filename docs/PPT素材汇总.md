## 幻灯片3：系统架构

**（插入 架构图.md 中的 Mermaid 分层架构图 PNG）**

### 三层六Agent架构
1. **评估层**（4 Agent 并行）：医疗·护理·社工·餐饮 四维评估
2. **编排层**（Orchestrator）：冲突消解 + 优先级排序 + 统一计划
3. **决策层**（Decision Agent）：合理性·安全性·可行性 三审终审

### 关键设计
- 双层冲突消解：规则引擎（硬编码）+ LLM推理（柔性）
- 4Agent并行调用（asyncio），延迟从4T→1T
- 模拟模式：无API也可完整演示

## 幻灯片5：案例1 — 王奶奶（轻度失能·社工主导）

**画像**：78岁，社区居家，高血压+骨关节炎，Barthel 85分
**核心发现**：
- GDS 10分 → 中度抑郁倾向
- 社会隔离 → 饮食质量下降（月降1.5kg）
- 医疗/护理风险低，**社工维度是主战场**

**Agent协同**：
```
医疗：血压偶有波动，无需调药 ✅
护理：加装浴室扶手即可 ✅
社工：🔴 紧急介入！心理评估+社区日照中心链接+志愿者结对 🔴
餐饮：链接老年餐桌 ← 社工介入后自然解决
```

**核心洞察**：**有时最好的处方不是药，而是社会连接。**

## 幻灯片6：案例2 — 李爷爷（中度失能·医疗护理并重）

**画像**：82岁，机构养老，糖尿病+冠心病+CKD3期，**8种药物**，Barthel 55分
**核心发现**：
- 🚨 格列美脲+美托洛尔 = 隐匿性低血糖（高风险）
- 🚨 二甲双胍1500mg/日 > CKD3期安全剂量
- 🚨 Morse 55跌倒高风险 + 近3月跌倒史

**多Agent协同价值**：
- 医疗Agent发现3处药物相互作用 → 建议换药+减量
- 护理Agent建议环境安全改造+Q2H巡视
- 餐饮Agent设计CKD+DM双重限制膳食
- 社工Agent以"下棋策略"类比做动机访谈 → 提升依从性

**核心洞察**：Polypharmacy是护工无法识别的"隐形杀手"——医疗Agent补上了这个致命空白。

## 幻灯片7：案例3 — 张爷爷（重度失能·护理主导·反客体化）

**画像**：89岁，完全卧床，重度阿尔茨海默+Barthel 0分+Braden 9分
**核心发现**：
- 骶尾部已有1期压疮 → Q2H翻身是生命线
- 低蛋白血症(28g/L)+体重骤降 → 营养升级
- 女儿"父亲不认得我了" → 家属哀伤辅导

**反客体化实践**：
> 传统系统输出："今日体温36.8℃，排便1次"
> CareMind输出："2026-06-07 播放《空城计》时，他的呼吸变平稳了。你的照片在他枕头右边，护理员说他有时会朝那个方向转头。"

**核心洞察**：Barthel是0分，但人的价值不是0分。

## 幻灯片8：技术选型

| 层级 | 选型 | 理由 |
|------|------|------|
| 语言 | Python 3.11+ | LLM调用生态最好 |
| LLM API | Claude API / 通义千问 | 结构化JSON强，中文医疗理解好 |
| 前端 | Streamlit | 零前端代码，竞赛演示最友好 |
| 数据建模 | Pydantic v2 | 严格schema保证多Agent数据契约 |
| 并行调用 | asyncio.gather() | 4评估Agent无依赖，并行降延迟 |
| 数据存储 | JSON文件 | 竞赛原型无数据库需求 |
| 冲突消解 | 规则引擎 + LLM双层 | 又快又准，可解释+全面 |

### 为什么轻量化？
- 不训练模型（调API + Prompt Engineering）
- 不建数据库（JSON文件 + Pydantic）
- 不写前端（Streamlit自动渲染）
- 核心逻辑约1000行Python，集中在Agent定义和协调

## 幻灯片9：创新点总结

### 1. 理论创新
- **"全人照护"的多Agent数字映射**：4个Agent分别对应生理·心理·社会·营养四个维度
- **"反客体化"的技术实践**：社工Agent生成情感叙事而非冰冷数据

### 2. 技术创新
- **双层冲突消解**：规则引擎 + LLM推理互补
- **并行评估架构**：4Agent无依赖，延迟从4T→1T
- **结构化输出契约**：Pydantic Schema保证6个Agent间的数据流一致性

### 3. 应用创新
- **填补Polypharmacy监管空白**：医疗Agent自动检测药物相互作用
- **赋能低学历护工**：降低专业医学认知的使用门槛
- **对接长护险政策**：评估报告可直接作为理赔凭证

## 幻灯片10：总结与展望

**一句话总结**：CareMind 不是在替代护工和医生，而是在数字层面搭建一座"医养结合的桥梁"——让医疗的专业性和养老的人性化在AI的协调下融合。

**下一步方向**：
- 接入真实IoT设备数据（智能床垫、跌倒检测、生命体征监测）
- 对接长护险评估系统，实现评估→计划→执行→理赔的全链路
- 语音交互降低护工使用门槛（方言识别）
- 从3个案例扩展到养老院实际部署验证
